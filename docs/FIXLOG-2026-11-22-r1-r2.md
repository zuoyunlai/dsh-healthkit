# 0.14.2 反哺台账（2026-11-22）

## 一、现象

0.14.1 真机复跑（desktop profile）报出两条判据噪声：

- R1 P1「装了但未启用 3 个（desktop）」——其中 @deepseek-ai/dsh-subagent-claude-code 明明在 `dsh.profile.bundles` 里；
- R2 P2「disabled 指向的包不在依赖里（疑似空转） 1 条」——指向 project-memory，而它正是用户自己在市场停用的包。

## 二、逐条核实（证据来自本机 `~/.dsh` 与 dshmarket 日志）

| 对象 | 结论 | 证据 |
|---|---|---|
| @deepseek-ai/dsh-subagent-claude-code | 误报（采集层判据） | 在 `dsh.profile.bundles` 第 29 项；判定却拿「剔掉 @deepseek-ai/* 的 thirdPartyBundles」比对依赖 |
| dsh-remote | 真丢行 | 依赖仍为 1.2.0；bundles 无此行；市场日志 2026-11-22T04:49Z 升级 1.2.0→1.3.0 被 CANCELLED（MARKET_UNLOADED），随后 OPERATION_BUSY |
| dsh-openrouter-providers | 真丢行 | 11-19 安装（日志 hot=true）；bundles 无此行；不在 `.dsh-market/state.json` 的 disabled 里；`~/.dsh/openrouter-providers.json` 不存在 |
| project-memory（R2） | 误报（停用记录认不出） | 市场记完整包名 `@yolk_vat-y/dsh-project-memory`，patch 行 id 是短 id `project-memory`，旧实现按尾段精确比 |

## 三、根因与修法

1. **`src/collect.mjs`**：`notBundledRaw` 复用了上面剔过 `@deepseek-ai/*` 的 `third`，于是任何官方作用域依赖即使已挂载也永远判「不在 bundles」→ 改为与**全量 `bundles`** 比对。
2. **`src/rules.mjs`**：新增 `normId`（去 scope、去 `dsh-` 前缀、小写），R1/R1b/R2b 共用同一套归一化，短 id 与完整包名互为同一包；空串不参与匹配，避免空对空。

## 四、回归

- 新增 `test/collect-bundle-scope.mjs`：已挂载官方依赖不许报 / 未挂载官方依赖**仍要**报（防「改过头变安全假绿」）/ R25 不受影响（核心 bundle 不在 dependencies 属正常）。
- `test/intent.mjs` 补两例：记录写全名 + patch 写短 id → R2b；反向记录写短名 + 依赖写全名 → R1b。
- 测试组数 45 → 46；README 标题同步（`docs-drift` 钉住）。

## 七、遗留（不在本批）

- `test/clean-symlink.mjs` 在本机跑不起来：Node 26 下 `junction` 的 `lstat().isSymbolicLink()` 返回 false，目录符号链接需权限（EPERM）；CI ubuntu 正常。
- 由此提示产品面疑点：`clean` 的「不跟随链接」守卫若依赖 `isSymbolicLink()`，在 Windows junction 上可能失效（可能把外部目录当普通目录统计/腾挪），需单独实测后再决定修法。
