# PLAN-2 —— 从「审计器」到「DSH 管家」

日期：2026-11-16　承接：PLAN-2026-11-16.md（P1 引擎层）　状态：P1 已落地

## 1 定位

对标「微软电脑管家」，但内核不照抄。

电脑管家的钩子是「帮你清出几个 G / 一键加速」。**这个钩子在 DSH 里是空的**，实测：

| 项 | 实测 |
| --- | --- |
| `~/.dsh` 总量 | 2.1–2.2 G |
| 其中必需 | `node_modules` 701M、`dsh-runtimes` 506M、`dsh-ops` 108M |
| `attachments`+`sessions` 在 30/60/90 天 TTL | **回收 0 MB**（最老会话 2026-10-19，还没到期） |
| 清理器实测可动 | 默认档 **37.3 MB**；含「需确认」档共 **84.9 MB** |

所以 DSH 管家的价值落在**体检 + 治理**：分数、趋势、可核的结论、可还原的修复。
清理只是配角，且必须可撤销——否则一次误删就把「可信」这件事赔光。

与之配套的两条差异点（电脑管家做不到）：

1. **每条结论可核**：findings 带 `ruleId#target` 指纹，能追到证据。
2. **结论会退役**：修好/失效的进退役库，不反复报（对照电脑管家的弹窗骚扰）。

## 4 P1 清理器设计

### 分组与风险档

| id | 标签 | 风险 | 判定 |
| --- | --- | --- | --- |
| `cache-image-gen` | 图片生成缓存 | 安全 | 可再生 |
| `cache-attachments` | 附件缩略图缓存 | 安全 | 可再生 |
| `backup-aged` | 过期配置备份 | 按龄 | `_backup` 下 mtime ≥14 天；**今天生成的 profile 备份绝不动** |
| `auditkit-stale-index` | 审计器过期索引 | 安全 | >48h 自动失效，重跑重建 |
| `mirror:<host>-<user>-22` | 远程工作区镜像 | **需确认** | machines.json 仍有该机器，删掉=删本地同步副本 |

### 回收区协议

```
执行：$DSH_HOME/dsh-auditkit/trash/<YYYYMMDD-HHmmss>/
        ├─ manifest.json   （原始路径、字节数、分组、还原截止时间）
        └─ items/001-<原名> …
还原：audit_clean action=restore batch=<批次>（原位置有同名则跳过并报冲突）
真删：audit_clean action=purge olderThanDays=7（默认 7 天；先 dryRun 可看候选）
全部还原后批次目录自动消失，不留垃圾
```

### 护栏（代码里硬挡，不靠调用方自觉）

- 必须在 `DSH_HOME` 之内，且不等于 home 本身
- 命中 `node_modules`/`sessions`/`attachments`/`skills`/`data`/`storages`/`llm-deepseek`/`.git`/credentials 一律拒绝
- `apply` 必须显式给 ids（不许「全清」语义）
- 需确认档没有 `confirm` 就跳过
- 只从 `scan()` 的结果里挑，不接受任意路径

## 5.1 P3 分数账本（已完成，2026-11-16）

- 账本：`$DSH_HOME/dsh-auditkit/history.jsonl`，append-only，上限 2000 条，超出丢最旧
- 记账放在**调用层**（CLI / 工具壳），`engine.audit()` 保持纯函数：只读承诺不被污染
- 读取按本地日期折叠（同日多次取最后一次），避免一天跑十次把趋势画歪
- 呈现：`--trend [days]` / `audit_trend`，含 sparkline、均值、最好/最差、P0 未关
- 验收：9 天序列 4.2→6.1，`delta=+1.1`、`avg7=4.96`、sparkline `▄▄▄▄▄▄▅▅▅`；空 home 实跑得 9.64/10（校准正常）
