# 架构审计修订台账（2026-11-17）

> 依据：软件架构师对 v0.11.1（`9231c82`）的架构审计，评分 6.4/10「需治理」，P0×2 / P1×7 / P2×3。
> 本文是**逐条修订台账**：每项写修前实测、修后实测、落点与守卫测试。
> 原则：不给「已修」这种自述结论，只给能复跑的证据。

## 一、P0

### A1 · 清理护栏对「终段同名目录」失效

- **修前**：`clean.mjs` 的 `FORBIDDEN` 写成 `[\\/]name([\\/]|\$)`，`\$` 是**转义的字面美元号**而不是结尾锚点。逐字照抄跑一遍：

  ```
  漏过  C:/_backup/node_modules      ← 终段就是受保护名
  挡下  C:/_backup/node_modules/pkg  ← 只有带子路径才挡
  漏过  C:/_backup/attachments
  漏过  C:/_backup/sessions
  ```
  `grep -rn 'FORBIDDEN' test/*.mjs` → 零命中：这条唯一守着不可逆删除的护栏从未被测过。

- **修后**：改用真锚点 `(^|[\\/])(…)([\\/]|$)`，并把名单抽成 `PROTECTED_NAMES`；`forbidden()` 导出给测试；`purge()` 增加二次校验——清单里只要有一项的原始路径命中护栏，整批拒绝删除（护栏漏过的历史批次靠这层兜住）。

  ```
  BLOCK  C:/_backup/node_modules / node_modules/pkg / attachments / sessions / .git / ~/.dsh/data
  pass   data-backup / mydata / sessions.db      ← 形近名不误挡
  ```

- **落点**：`src/clean.mjs`（护栏 + purge）、`index.js`（purge 摘要报出被拒批次）
- **守卫测试**：`test/clean-guard.mjs` —— 8 个受保护名 × 3 种位置 + 5 个形近名 + purge 二次校验，共 **33 项断言**

### A2 · 坏 profile 静默消失（体检器把「坏了」报成「没有」）

- **修前**：`collect.mjs` 里一句 `if (!pkg) continue;`。临时 HOME（good + corrupt 两个 profile）实测：

  ```
  profiles collected: [ 'good' ]        ← corrupt 整个消失
  findings 提到 corrupt 的条数: 0
  ```
- **修后**：`facts.profileErrors[]` 记下 `{name, dir, reason}`（区分 `parse-error` / `missing-package-json`），新规则 **R24**（reliability / P0 / MEASURED）逐条报出；P0 触发封顶，`总分 ≤ 5.0`，不再被高分掩盖。空残留目录（既无 package.json 也无 node_modules）静默跳过，不制造噪声。
- **落点**：`src/collect.mjs`、`src/rules.mjs`
- **守卫测试**：`test/profile-errors.mjs` —— **13 项断言**（含「空残留目录不许报」「指纹各不相同」「封顶必须生效」）

## 五、没做的事（附理由）

1. **规则登记表 / registry（审计 ③-2）**：本轮只做了「出口校验 + 分层守门」，没抽 registry。理由：35 条规则、单人维护，registry 的价值主要在产出自描述文档；在 B1 已经把「维度/严重度非法」喊出来之后，它的边际收益低于改动面。留作下一轮。
2. **完整 viewmodel 抽取（③-3）**：只做了「阈值单一真源」这一半。表现层合并（工具 render / 服务端 HTML / React）会动三处渲染代码，风险大于收益，且 UI 刚经历一轮重做，宜等稳定。
3. **`headlineOf` 的 6/8 阈值**：属文案分档（措辞选择），不是评分口径，未并入 bands。
4. **规则 DSL**：明确不做（审计也建议不做）——解释器只会把「配置写错静默失效」扩散。
